# 2026-10-19 华为云实验慢速复盘

## 结果

- 实验：KooLabs 2333《30分钟轻松搭建网站应用》
- 实际环境：13:19 开始，14:09 结束，约 50 分钟
- 交付：VPC/ECS/RDS/LAMP/WordPress 全部搭建并验证；平台报告 83%，6 个检查点过 5 个
- 未过项：7.1“进入数据库配置页面”，实际 7.2 安装和 7.3 登录均已成功

## 时间都花在哪

| 环节 | 约耗时 | 具体表现 |
|---|---:|---|
| Playwright CLI 启动与命令重试 | 8 分钟 | 每条命令新起 `npx`；PowerShell 引号、`$1`、`document` 作用域等错误反复重试 |
| 整页 snapshot 与找元素 | 6 分钟 | 一次 600-900 行，真正需要的只有一个按钮 |
| Angular/tiny3 自定义组件 | 12 分钟 | 隐藏模板节点、下拉菜单、坐标点击；安全组还发现平台检查的是默认安全组 |
| RDS 主备创建等待 | 13 分钟 | 创建后约 7 分钟才可用，详情页还缓存“创建中” |
| 7.1 校验排查 | 6 分钟 | 撤下 wp-config、等待校验、再恢复，仍未翻绿 |
| 登录/标签页切换 | 3 分钟 | 本机浏览器、实验桌面、控制台三套会话来回切换 |

## 根因

1. **控制层不是常驻的**：每个动作都重新启动浏览器/CLI，固定开销远大于动作本身。
2. **查询粒度太粗**：整页快照适合探索，不适合已知目标；应该按选择器/文本返回 1-20 个候选。
3. **失败反馈太慢**：默认 30 秒超时，错误选择器会把一次小失误放大成半分钟。
4. **没有检查点驱动**：只在最后看报告，导致 2.3 和 7.1 的问题发现太晚。
5. **顺序不够并行**：RDS 是长耗时项，应该先下单，再去做 ECS 和 LAMP。
6. **凭据处理不严谨**：临时密码进入了工具调用文本；应改为本地 secret 文件/环境变量，并做日志脱敏。

## 已经做的改进

- 常驻 `dop.py`：浏览器、UIA、截图、OCR、鼠标键盘共用一个进程。
- 紧凑查询：`browser.query` 只返回匹配项和边界框，不再整页 dump。
- 多选择器重试：`browser.click` 支持 `selectors` 列表，命中即停，默认 4 秒超时。
- 批量动作：`batch` 一次 HTTP 调用执行多步，减少往返。
- 原生窗口：`win.list/tree/click/type/keys`，走 Windows UI Automation。
- 画布兜底：`screen.capture/ocr/find_text/click_text`，用 Windows 自带中文 OCR。
- CDP 接管：`browser.attach` 可连接已开远程调试的 Edge。
- 响应捕获：`browser.capture_response` 可抓点击触发的 API JSON，用于报告检查点。

## 实测延迟

同一台机器、常驻进程已启动：

| 命令 | 平均 | 最小 | 最大 |
|---|---:|---:|---:|
| `system.info` | 26.8ms | 1.6ms | 76.9ms |
| `win.list` | 81.1ms | 48.5ms | 131.4ms |
| `browser.text` | 16.7ms | 6.9ms | 24.1ms |
| `browser.query` | 24.1ms | 14.9ms | 37.1ms |
| `screen.capture` | 241.7ms | 214.2ms | 286.7ms |

对照之前的 `npx playwright-cli` 单次 2-10 秒启动，交互链路大约快了一个数量级。

## 下次的硬规则

1. 先用 `dop.py` 常驻层，不再为每个动作起 CLI。
2. 目标明确时用 `browser.query`/`find_text`，只在未知页面才用整页快照。
3. 任何点击/填表都给 2-3 个候选选择器，超时压到 4 秒。
4. 长耗时资源先下单，再做可并行的短任务。
5. 每完成一个平台检查点就看一次报告，不把问题留到最后。
6. 密码/Token 只从本地 secret 读取，不打印、不写进命令历史。
